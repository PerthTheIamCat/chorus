# Chorus harness roadmap

## Destination

A phased, decided roadmap spec that turns macOS Chorus into a first-class desktop agent harness: every area below has a decided scope and approach, ordered into phases, and ready to be split into implementation issues under `.scratch/`. Planning ends at the reviewed roadmap; implementation is a later effort per area.

Areas: harness eval · agent-facing control surface (CLI/MCP) · agent-as-orchestrator with worktrees · workbench layout · file/folder/code viewer · diff viewer + review loop · subagent visibility · router quality · chat mode · attachment UX · headless core boundary (remote-ready) · feature gaps found in other harnesses.

## Notes

- **Audience**: Perth first, but plan for a public release later (onboarding/distribution stays in the fog until then).
- **Platform**: macOS only. Every new feature keeps its logic in Rust; Swift only draws and takes input (CLAUDE.md rule 2.3). The ledger stays the single source of truth (rule 2.2).
- **Measure, don't guess**: the harness eval (ticket 10) is how features and the router get judged, the same way `chorus bench` is a baseline that must not regress.
- **Phase order (agreed)**: 1 Foundation (harness eval + agent control surface) → 2 Workbench UI (layout, file viewer, diff) → 3 Multi-agent (subagents, orchestration) → 4 Router quality → 5 Chat mode + attachment UX → 6 Remote/mobile (designed, not built).
- **Standing preferences from charting**:
  - Orchestration is **agent-driven**: an agent calls Chorus (CLI/MCP) to spawn, message, wait on, and collect other agents. Chorus does not run its own planner.
  - Parallel agents that write get **their own git worktree**. Read-only agents may share the main tree.
  - File handling is **view-first**: beautiful file tree, folder, and code display with syntax highlighting, plus "Open in external editor". No in-app editing, no IDE.
  - Diff: unified **and** side-by-side, scoped per turn / per agent / per session, with **inline comments sent back to the agent** to fix.
  - Subagents: tree with live status, per-child transcript, per-child tokens, and stop/message where bridges allow. It must be a clear, polished UI.
  - Router: **remove the countdown** and bias toward **cheaper models**, since it currently over-picks strong ones.
  - Chat mode: no-project, read-only sessions backed by existing agent CLIs and local Ollama, with a model picker for which model answers.
  - Remote/mobile: this map only decides that the core can run as a headless daemon with an API. The mobile app, pairing, and relay are not built.
- **UI tickets** (prototype type) must consult the skills `anti-ui-slop`, `macos-design-guidelines`, and `ui-ux-pro-max`, and follow the existing design notes in `docs/ref/` (`Chorus Desktop Blueprint`).
- Research output goes to `./research/NN-<slug>.md` (the convention from `chorus-tools-router`). Cite primary sources.
- Prior effort: [chorus-tools-router](../chorus-tools-router/map.md), which already decided attachments policy, the integration catalog, and router v1.

## Decisions so far

- [Desktop harness feature survey](./issues/01-desktop-harness-survey.md): Surveyed 7 leading harnesses (Codex app, Claude Code Desktop, Cursor, Antigravity, Zed ACP, Windsurf, Kiro). Frontier harnesses converge on inline diff comments fed back to agent, Git worktree isolation for parallel write agents, view-first supervisor UI (file tree, code viewer, external editor hand-off), and turn-by-turn checkpoint rewind. Ranked 12 gaps for Chorus led by inline diff comments and worktree isolation.
- [Multi-agent orchestrator survey](./issues/02-multi-agent-orchestrator-survey.md): Surveyed 10+ orchestrators; identified Stably Orca (`stablyai/orca`). Confirmed local harnesses converge on Git worktrees (sub-200ms setup, zero-copy storage) with `.worktreeinclude` env copying and dynamic `$PORT` allocation. Recommended internal Rust worktree engine + MCP agent control surface (`chorus_spawn_agent`, `chorus_send_message`, `chorus_collect_results` with compact briefs to protect parent context).
- [What makes agents effective in OSS harnesses](./issues/03-oss-harness-effectiveness-survey.md): Harness scaffolding creates double-digit performance swings (+10.7 pp from ACI design, +12–13 pp from test feedback, ~30%→70% file localization via AST RepoMaps). Ranked 8 core harness features for Chorus: automated post-edit verification loops, tool output compaction/guardrails, AST RepoMap, universal rules projection (`AGENTS.md`/`CLAUDE.md`), LSP diagnostics, plan mode, hooks, and inline diff review.
- [Chat app survey](./issues/04-chat-app-survey.md): Analyzed 7 desktop chat apps across 11 dimensions. Recommended: mid-conversation model switching via ledger SoT, turn forking/regeneration mapped to `ledger::fork`, view-first artifacts drawer (code/SVG/Mermaid), local Ollama as equal peer to agent CLIs, SQLite FTS5 instant search, and "Promote to Task" workflow distilling chat into a project `Brief`.
- [Remote and mobile control survey](./issues/05-remote-mobile-survey.md): Surveyed Claude Code remote, Happy, Omnara, and Codex mobile. Identified requirement for async `Interaction` state machine (replacing blocking C FFI callbacks), sequence-numbered SSE replay matching ledger event IDs, and a headless daemon (`chorusd`) over UDS/HTTP with webhook notifications. Mobile acts as steering/approval layer rather than editor.
- [Subagent visibility in ACP bridges](./issues/06-subagent-visibility-in-bridges.md): Two incompatible bridge models: Codex multiplexes distinct child `sessionId`s via `subagent_spawned`, while Claude tags tool calls with `_meta.claudeCode.parentToolUseId` on parent `sessionId`. Identified critical bug in Chorus (Claude child prose/tools currently pollute parent transcript; Codex child tools are dropped). Neither bridge supports per-child cancel/tokens/message. Recommended unified Subagent Normalizer layer in `chorus-acp`.
- [Local router model approaches](./issues/07-local-router-approaches.md): Current router over-picks strong models due to hardcoded Review floors, lack of a cost-penalty term in utility distance, and small-LLM difficulty inflation. Recommended in-process embedding + calibrated linear probe (3–8 ms, zero daemon setup) or two-stage cascade with cost penalty, learning from user overrides via kNN in SQLite.
- [macOS code and diff rendering components](./issues/08-macos-code-and-diff-components.md): All diffing, hunk extraction, and syntax highlight spans computed in Rust (`similar` + `syntect`/`tree-sitter`). Rendered natively in AppKit via TextKit 2 / `NSOutlineView` (virtualized, 120Hz scrolling, 50k+ files). Rust pre-aligns side-by-side diff pairs to avoid dual-scroll drift. Disqualified WKWebView/Monaco and pure-Swift highlighters.
- [Harness eval methodology](./issues/09-harness-eval-methodology.md): Harnesses create up to 40× token variance and 10–20% solve rate differences. Recommended a 3-tier eval (invariants, router gate, and 24-task paired real-session suite in native Git worktrees reading directly from SQLite ledger).
- [Harness eval design](./issues/10-harness-eval-design.md): 60 paired tasks (30 Thai, 30 English) across 4 engineering domains evaluated in a dual-agent matrix (Codex and Claude Code). Gated on Pass@1, Token Efficiency (<10% regression), zero tool loops, and context bloat ratio. Tier 0 (<2s) on pre-commit, Tier 1 (<30s router gate) on PR/CI, Tier 2 (full live suite) manual/pre-release.
- [Agent-facing control surface](./issues/11-agent-control-surface.md): Dual interface (Streamable-HTTP MCP server + CLI over Unix Domain Socket `.chorus/engine.sock`). Full capability set: spawn/message/collect/cancel agents, live task checklist update, jump-to-file in UI, request interactive review, macOS notifications with chime, and worktree verification. Custom agent roles with **AI Role Generator** (UI + dynamic subagent synthesis) editable via Settings UI and `.chorus/agents/*.md`, with configurable concurrency limit (1–8).
- [Router quality policy](./issues/17-router-quality-policy.md): In-process embedding linear probe (3–8 ms, zero Ollama daemon) with cost-biased utility optimization defaulting to efficient tiers (`gpt-5-codex` / low effort). 5s countdown eliminated in favor of instant dispatch + non-blocking borderline gating. Subtle UI pill with 1-click model regeneration, and SQLite vector kNN learning flywheel from user overrides.
- [Chat mode](./issues/18-chat-mode.md): Workspace-free, read-only session backed by ledger SoT. Dedicated "Chats" section in sidebar above Projects. Backed by local Ollama & agent CLIs with mid-turn model switching, dual split/compare, FTS5 instant search, view-first Artifacts drawer, and one-click "Promote to Task" workflow distilling context into a project `Brief`.
- [Workbench layout](./issues/13-workbench-layout.md): 4-column adaptive layout (Universal Sidebar 260px, Workspace Explorer 240px `⌘B` with virtualized file tree & worktrees, Center Stage splitting dynamically between Thread and Code Viewer, and Inspector 340px `⌥⌘I` with Diffs/Subagents/Context/Memory). Preserves Floating Glass Cards aesthetic with resizable split dividers. All logic in Rust.
- [Diff viewer and review loop](./issues/15-diff-viewer-and-review-loop.md): Dual view modes (Unified & Split side-by-side with Rust spacer alignment). 4 scopes (Latest Turn, Current Agent, Session, Agent Worktree). Inline review comment loop (gutter hover trigger, pending comments bar, and one-click "Send to Agent ⌘↩" steering loop) with per-hunk reverse rollback.
- [Subagent visibility UX](./issues/16-subagent-visibility-ux.md): Native macOS hierarchy tree in Inspector with live status badges (`⟳ Running`, `✓ Completed`, durations, tool counts). Dedicated child transcript drawer isolates child thoughts and tool outputs from main thread. Separates synchronous ACP subagents from parallel Chorus worktrees in sidebar.
- [Attachment UX polish](./issues/19-attachment-ux.md): Premium native SF Symbols (`photo`, `doc.text`) instead of emojis. Clipboard `⌘V` stages thumbnail chips with Spacebar Quick Look preview. Dropzones across composer and thread. `⌘L` context chip shortcut from Code/Diff viewer. Model vision badges (`eye` vs `exclamationmark.triangle`) with 1-click fallback.
- [File, folder, and code viewer](./issues/14-file-and-code-viewer.md): High-performance AppKit `NSOutlineView` file tree (50k+ files at 120Hz) with Git badges and live agent focus ring (`●`). Read-only TextKit 2 code viewer in SF Mono with Rust-computed syntax spans. Auto-detects installed editors (Cursor, VS Code, Zed) with one-click `⇧⌘E` hand-off.
- [Headless core boundary](./issues/20-headless-core-boundary.md): Decoupled `chorusd` background daemon communicating over Unix Domain Socket (`~/.chorus/engine.sock`) and SSE streaming with `Last-Event-ID` SQLite ledger replay. Async `Interaction` state machine replaces blocking C FFI. Non-disruptive `⌘Q` lifecycle allows background runs with native macOS chimes/notifications. Local auth via socket permissions (`0600`) and keychain tokens; mTLS/WireGuard for future remote pairing.
- [Agent-driven orchestration and worktrees](./issues/12-agent-orchestration-and-worktrees.md): Sub-200ms Git worktrees under `.chorus/worktrees/` on dedicated branches with `.worktreeinclude` env copying and dynamic `$PORT` allocation. SQLite Ledger tracks hierarchical lineage (`parent_session_id`). Parent context protected via compact structured briefs (summary, diff stat, verification test outputs) preventing token bloat. Default 3-agent concurrency cap. Live user supervision with mid-flight steering (`⌘↩`) and automated clean merge / conflict quarantine.
- [Feature gap triage](./issues/21-feature-gap-triage.md): Triaged 12 survey gaps: ruled into phases (Phase 1: macOS notifications/chimes, verification hooks, project rules projection, granular ask-each permissions; Phase 2: live checklist card, 1-click git commit/PR flow; Phase 3: dynamic port browser trigger; Phase 4: monetary cost accounting; Phase 5: SQLite FTS5 search, session export/share); ruled into fog (embedded WKWebView, cloud sync); ruled out of scope (embedded PTY terminal, in-app code editor).
- [Roadmap sequencing and handoff](./issues/22-roadmap-sequencing-and-handoff.md): Finalized 6-phase implementation roadmap with empirical exit criteria tied to the harness eval suite. All 22 tickets resolved. Master implementation specification delivered in [ROADMAP.md](./ROADMAP.md).


## Not yet specified

- **Public release**: onboarding for new users, notarization and `.app` signing, auto-update, crash reporting and opt-in telemetry, docs site, licensing.
- **Mobile client**: app shape, device pairing and auth, relay vs. direct tunnel, push notifications, and which actions are allowed remotely. This waits on the headless core decision.
- **Direct API-key backends** for chat (Anthropic/OpenAI/OpenRouter keys) beyond agent CLIs and Ollama.
- **Memory and context upgrades** that the harness eval may justify, such as embedding search (sqlite-vec), cross-session memory, and project rules/instructions management.
- **Cost accounting**: monetary cost per turn, session, or subagent. This depends on what bridges report.
- **Spec-to-issues breakdown** for each area once its decision lands.

## Out of scope

- **Chorus-run planner orchestration** (Chorus splitting a task by itself): the user chose agent-driven orchestration only.
- **In-app file editing / IDE features (LSP, refactors)**: the user chose view-first plus external editor.
- **Windows / WinUI and other non-macOS clients** for this effort.
- **Building the mobile app** in this effort. Only the remote-ready core boundary is decided.
