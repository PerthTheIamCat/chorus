# Integration catalog research: Graft, Serena, RTK, Headroom

Reviewed 2026-10-05 against first-party repositories/docs. This compares each product's current form and how it fits Chorus; it does not endorse or install any tool.

## Chorus integration points inspected

- Chorus reads workspace MCP servers from `.chorus/mcp.json`, accepts Claude-shaped `mcpServers` objects or ACP arrays, redacts env/header values in its listing, and passes enabled entries into ACP `session/new`. The built-in Chorus MCP service currently exposes its own memory tool. See [`mcp_config.rs`](../../../crates/chorus-core/src/mcp_config.rs) and [`session.rs`](../../../crates/chorus-cli/src/session.rs).
- Skills currently have a canonical project location at `.chorus/skills/<name>/SKILL.md`; Chorus projects them to `.claude/skills/` for Claude and supplies an index to agents without native skill loading. The macOS Settings screen lists visible skills. See [`skills.rs`](../../../crates/chorus-core/src/skills.rs) and [`Settings.swift`](../../../apps/macos/Sources/Chorus/Settings.swift).
- This means MCP servers can be made available to agents per Chorus session today through the existing configuration path. CLI hooks/wrappers and agent-native plugins are different integration types: they need an executable/runtime and may edit per-agent files outside Chorus's own config. A catalog should record these effects and install ownership rather than treating every item as an MCP server.

## Comparison

| Tool | Purpose and integration type | macOS / installation lifecycle | Source and license | How a Chorus agent can consume it |
|---|---|---|---|---|
| **Graft** | Codebase context graph. CLI (`graft ask`, `grep`, etc.), MCP server (`graft mcp`), plus optional skills/instruction wiring and post-edit hooks. Builds a local regenerable `graft/` cache; deeper semantic summaries can call a model through the provider/key configured by the user, while the structural graph is local and model-free. [README](https://github.com/trailhq/Graft#readme) | npm CLI (`npm install -g @nanonets/graft`; `npx` also documented); macOS compatibility is implied by its Node CLI, but the reviewed README gives no dedicated macOS matrix. `graft init` can modify project agent files and user-level Codex config/hooks; it supports `--dry-run`, `--no-global`, `--no-mcp`, `--no-hooks`. `graft upgrade` updates the CLI; `graft uninstall` removes files/config entries it wrote, with flags to retain cache or skip global files. [Install/integration](https://github.com/trailhq/Graft#quick-start) · [lifecycle](https://github.com/trailhq/Graft#cli) | Repository moved from `NanoNets/context-graph-engine` to `trailhq/Graft`; README documents the npm package `@nanonets/graft`. MIT. [License](https://github.com/trailhq/Graft/blob/main/LICENSE) | Best Chorus fit is the existing MCP/ACP path (Graft exposes six graph tools). For CLI-first use, Chorus can make its executable available to the launched process and document invocation; its native hooks/skill integration may conflict with Chorus-managed agent config, so catalog installation should avoid silently running `graft init` or explicitly preview and track every mutation. |
| **Serena** | Semantic coding toolkit: symbol-level retrieval/editing/refactoring and memory. MCP server over stdio or HTTP; internal language support uses LSP by default. The JetBrains backend is a separate paid plugin. [Repository](https://github.com/oraios/serena) | Official quick start manages it with `uv`: `uv tool install -p 3.13 serena-agent`, followed by `serena init`; the repo documents MCP launch configuration and macOS Claude Desktop usage. Serena can be run as a local subprocess or HTTP server. The reviewed quick start describes no product-specific upgrade/uninstall flow; external `uv` manages the user-level tool install, and an enabled Chorus project would need its MCP entry removed to disable it. [Quick start](https://github.com/oraios/serena#quick-start) | Serena application is GPL-3.0-or-later; SolidLSP component is MIT. A combined distribution is GPL. This is a material catalog metadata item. [License](https://github.com/oraios/serena#license) | Direct MCP/ACP integration: pass an stdio launch command or HTTP URL in the project MCP config. Its project-specific settings and tools can then be available in that agent session. Chorus should treat Serena's own project initialization/config as a separate, reviewable step. |
| **RTK** | Rust CLI proxy that rewrites common shell commands and filters their output to reduce context. It is primarily an executable plus optional agent hooks/plugins/instructions, not an MCP server. [Repository](https://github.com/rtk-ai/rtk) | Explicit macOS support: Homebrew, installer, Cargo, and Apple Silicon/Intel binaries. `rtk init` installs hooks/config for supported agents and can be project- or user-scoped. Removal documented as `rtk init -g --uninstall` (hook/docs/settings entry), plus package-manager removal of binary. [Install and setup](https://github.com/rtk-ai/rtk#installation) · [uninstall](https://github.com/rtk-ai/rtk#uninstall) | Apache-2.0. [License](https://github.com/rtk-ai/rtk/blob/master/LICENSE) | Agent can invoke `rtk <command>` through shell, or receive compact output through RTK's supported hooks when the agent runtime exposes them. Chorus can provide the executable path, but transparent rewriting requires hook support; running vendor `rtk init` could write global agent files and should be avoided or surfaced for approval. |
| **Headroom** | Context/tool-output compression, reversible compression/retrieval, stats, and optional cross-agent memory. Offers local libraries, HTTP proxy/wrappers, and an MCP server (`headroom_compress`, `headroom_retrieve`, `headroom_stats`). MCP tools are on-demand agent calls; proxy/wrapper mode transforms request traffic. [Repository](https://github.com/headroomlabs-ai/headroom) · [MCP docs](https://github.com/headroomlabs-ai/headroom/blob/main/wiki/mcp.md) | Python CLI/runtime via `uv tool`, pip/pipx, plus TypeScript library and Docker. macOS Apple Silicon wheels are supported; Intel macOS has documented ONNX runtime caveats. `headroom update` updates supported Python installs; `headroom mcp install` and `headroom unwrap <tool>` wire/undo integrations for supported hosts. Reviewed docs do not describe one universal uninstall command for every installation type. [Install/update](https://github.com/headroomlabs-ai/headroom#install) · [macOS notes](https://github.com/headroomlabs-ai/headroom#uv-pipx-and-mcp-clients-that-dont-inherit-your-path) | Apache-2.0. [License](https://github.com/headroomlabs-ai/headroom/blob/main/LICENSE) | MCP-only mode fits Chorus's existing ACP server array. A local absolute executable path may be necessary where the agent process lacks the interactive shell PATH. Proxy/wrap mode is a separate routing choice and changes the model request path; it should be represented separately from merely enabling MCP. |

## Catalog implications

1. Model integrations by capability/runtime type (`mcp_stdio`, `mcp_http`, `cli`, `agent_hook`, `skill`, `proxy`, `library`) instead of a single generic “tool” shape. A product can declare several capabilities.
2. Keep user-level installation distinct from project-level enablement. Store version, source URL, license, executable/runtime path, install method, and files/config entries owned by Chorus. For project enablement, show the MCP/hook/skill effects and let the user disable or remove Chorus-owned wiring without deleting a shared user-level binary.
3. Prefer Chorus-owned adapters for config projection over invoking vendor `init` commands as opaque install steps. Graft and RTK vendor installers can write project and user-level files; preview, scope, ownership, and rollback are prerequisites for safe catalog installation.
4. MCP is the lowest-friction common denominator for the current agent launch architecture, but it cannot represent RTK's transparent shell-output rewriting or Headroom's proxy path. Those require separately designed runtime/hook/proxy support.
5. Curated catalog entries need version-pinned sources and license review. Serena's GPL application license differs from the MIT SolidLSP dependency; catalog approval should distinguish using its service as a dependency from copying or bundling source code.
